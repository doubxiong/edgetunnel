## 二、Cloudflare 面板变量（升级后按这张表设）

| 变量 | 建议值 | 为什么 |
|---|---|---|
| `ADMIN` | 不变 | 面板登录密码；改它等于换订阅 TOKEN |
| `KV` | 绑定不变 | 面板数据存这里，升级不迁移数据 |
| `UUID` | 建议设为固定 UUIDv4 | 固定之后客户端订阅不用改；不设则随 `ADMIN`/`KEY` 变化 |
| `PRELOAD_RACE_DIAL` | `1` | 首次直连先用 DoH 并发查 A/AAAA 再竞速拨号；上游已默认关闭，必须显式打开 |
| `TCP_CONCURRENT_DIAL` | `2` | **反直觉**：并发拨号越高建连越快、但 IP 切换越频繁；抖动场景要往低里调 |
| `PROXY_CONCURRENT_DIAL` | `2` | 同上，作用于反代（proxyip）侧 |
| `PROXYIP` | 建议自建 | 默认 `proxyip.cmliussss.net` 是共享回源，晚高峰拥塞会放大抖动；换成自己的 VPS/Worker 回源，等于把「回源段」从共享换独享 |
| `DEBUG` | 暂时 `1`，调完关掉 | 调参期看日志；长期开着会增加日志量 |

## 三、客户端侧（mihomo）

- 订阅里保留多个优选 IP，不要把节点地址写死成单个 IP。
- `url-test`：`interval: 240`、`tolerance: 60`、`lazy: false`；探测 URL 用 `http://www.gstatic.com/generate_204`。
- 只换名字、走同一路径的近似节点要删掉，否则选择器会来回跳。

## 四、部署后必须验证的三件事

1. 打开 `https://<你的域名>/admin`，能登录 → 说明 Worker 正常、KV 绑定还在。
2. 请求 `https://<你的域名>/version`，返回数字版本号 → 确认真的是新版本，不是旧缓存。
3. 客户端测一次大文件下载（>100MB）：不再出现中途归零/长时间无响应，才算「CPU 超时」这条修好了。

## 六、自建 PROXYIP 的思路（未实施）

- 在自有 VPS 上起一个只做转发的 Xray/sing-box 入站（VLESS+TLS 或 SOCKS5），把 `PROXYIP` 指向它。
- 目的不是「更快」，是「不跟别人挤同一台回源」；抖动多数来自回源侧的排队，而不是你家里的带宽。
- 实施前先量一次：对同一目标连续 20 次取 RTT 的 p50/p95，对比共享 proxyip 与自建回源的差距，有差距再上。
